## 1. 핵심 방법론 추천 (3개)

### ① **Deep Umbra 논문** (page 13, **우리 프로젝트 옆에 직접 인용**)
- **URL**: http://evl.uic.edu/shadows
- **무엇**: GAN(Generator + Discriminator)으로 일조/그림자 누적 맵 생성
- **데이터**: 100+ 도시 × 6대륙 (Global Shadow Dataset)
- **성능**: RMSE 0.063, MAE 0.028, SSIM 0.90 (K-fold)
- **왜 추천했나**: 우리 프로젝트의 "자연 그늘" 피처를 **단순 기하 → DSM 기반 누적 그림자**로 진화시키라는 신호
- **✅ 우리가 한 것**: 풀 GAN 학습 대신 **DSM(흑석동 NGII) + 4시점(10·12·14·16시) ray-cast**로 단순화 (`src/cv_dsm_heukseok.py`)
- **🔲 안 한 것**: 풀 GAN 학습은 시간·데이터 부담으로 보류

### ② **단계별 전략 6 STEP** (page 19~25)
교수님이 제시한 표준 워크플로우:

| STEP | 내용 | 우리 적용 |
|---|---|---|
| 1 | 목표 설정 및 평가 지표 선정 | ✅ Score 7 피처 정의 |
| 2 | 필요한 도구 & 데이터 판별 | ✅ 9종 데이터, 12개 모듈 |
| 3 | 단계 세분화 및 구체화 | ✅ 5단계 파이프라인 (`main.py`) |
| 4 | 모듈화 → 컨텍스트 & 하네스 설계 | △ 부분 적용 (다음 ③ 참고) |
| 5 | 단계별 구현 및 검토 | ✅ 각 모듈 단독 실행 + 캐시 검증 |
| 6 | 전체 워크플로우 고도화 | ✅ Streamlit 대시보드 + 사용자 피드백 반영 |

### ③ **컨텍스트 + 하네스 설계** (page 23~24)
- **컨텍스트** (시스템 프롬프트): 역할·기준·출력형식(JSON)·이미지+텍스트 배치·CoT
- **하네스**: 출력 검증 / 오류 재시도 / 중간 저장 / 비용 추적
- **검증 두 차원**:
  - 기술적: JSON 파싱 오류율, 호출 실패율
  - 내용적: VLM 판단 vs 사람 판단 일치도
- **✅ 우리 적용**: `llm_rationale.py`에 JSON 출력 + 룰베이스 fallback
- **🔲 안 한 것**: 자동 재시도, 비용 추적, 중간 체크포인트 — **CV-D(멀티모달) 가면 필요**

## 3. 가로환경 평가 (page 22) — 표준 흐름

**1단계 — 이미지 데이터 수집**
- 도로망 데이터 받기 (브이월드)
- 대상지 구역 설정 (사용자 입력)
- 도로망 위에 이미지 포인트 생성
- 거리뷰 이미지 다운로드

**우리 적용**:
- ✅ 도로망: V-World 대신 **OSMnx walkable highway** (더 풍부)
- ✅ 대상지: 동작구 BBOX + 흑석동 경계
- ✅ 격자 중심을 포인트로 사용 (도로망 위 포인트와 5m 이내만)
- ✅ Mapillary로 거리뷰 다운로드

**2단계 — 이미지 지표 측정**
- 조작적 정의/측정방법/판단기준 수립
- API 반복 측정 후 GIS 파일로 변환

**우리 적용**:
- ✅ `shade_deficit = (도로+보도) × (1 − 건물 − 식생)` — 명시적 공식
- ✅ SegFormer 19 클래스 → GeoJSON/CSV 변환

## 4. ⭐ 최근 LLM 기반 거리환경평가 연구 추천 (page 40~42, **가장 중요**)

이 부분이 교수님이 가장 강조한 최신 방법론입니다.

### 4-1. 거시적 도시 평가 (page 40)
| 지표 | GPT-4o R² | ResNet R² | 격차 |
|---|---|---|---|
| 빈곤도 (Poverty) | **0.69** | 0.29 | +0.40 |
| 가로수 피복도 (Tree Canopy) | **0.40** | 0.16 | +0.24 |
| 레드라이닝 추정 | **0.58 SD** (실측 0.64와 통계적으로 동일) | — | — |

**📌 권장 사항 (Recommendations)**
- ⭐ **Reason-then-Estimate 파이프라인**:
  - MLLM에게 바로 점수 요청 X
  - 프롬프트로 "거리에 쓰레기·잡초·깨진 창문 등 시각적 단서를 먼저 서술" → 그 후 0~1 점수 매핑
  - JSON 포맷 강제
- ⭐ **Self-consistency 검증**:
  - 동일 이미지 5번 반복 평가 → 평균
  - 예측 안정성 확보

### 4-2. 미시적 가로 시설물 (page 41) — 한계와 보완
- MLLM(GPT-4V, Gemini)은 **로고 인식·건축양식**엔 강함
- 그러나 **보행자/차량 정확 계수, 도로폭·건물높이 측정**엔 약함
  - Gemini가 실제 12m 도로를 22.2m로, 24m 도로를 74m로 추정한 사례

**📌 권장 사항**
- ⭐ **기준 객체 치수 제공**: "표준 승용차 4.8m, 사람 1.7m, 차선 3.7m"를 프롬프트에 명시
- ⭐ **MLLM + 특화 객체탐지 모델 결합**: MLLM 단독 사용 X

### 4-3. 작은 객체 탐지 한계 (page 42) — 어텐션 vs 인지
- 모델 내부 어텐션 지도는 "어디를 봐야 하는지" 알지만 **해상도 병목**으로 정확 인지 못함
- 객체 크기가 이미지의 0.5% 미만이면 GPT-4o 인식률 −7%, 오픈소스는 −24%
- 방해 요소 25개 이상이면 객체 탐지 성능 선형 추락
- 교통 표지판 텍스트는 ResNet50 Fixed-Size(256×256)가 **재현율 96%, 정확도 88.5%**

**📌 권장 사항**
- ⭐ **자동 시각적 크롭 (Crop-Upsample) 필수**:
  - 볼라드·소형 표지판·노면 결함 평가 시 원본 SVI 통째 입력 X
  - 사전 객체 탐지로 ROI 찾고 → crop & upsample → MLLM 입력

## 5. 우리 프로젝트가 적용한 것 vs 적용 안 한 것

### ✅ 적용 완료
1. **Deep Umbra 영감** → CV-DSM (DSM + 4시점 ray-cast로 단순화)
2. **단계별 전략 6 STEP** → 자연스럽게 따름
3. **SAM** → Mobile-SAM zero-shot (CV-A)
4. **V-World 항공사진** → CV-A WMTS 48 타일 합성
5. **거리뷰** → Mapillary (CV-B)
6. **이미지 지표 측정** → CV-B SegFormer 그늘 결핍 공식
7. **JSON 출력** → LLM rationale (부분)
8. **객체 탐지 + segmentation 결합** → CV-A(SAM·인스턴스) + CV-B(SegFormer·시맨틱)

### 🔲 아직 적용 안 함 (다음 단계 후보)
| 추천 | 우리 상태 | 적용 시 효과 |
|---|---|---|
| **Reason-then-Estimate** | CV-B는 SegFormer 한 번 호출, MLLM 없음 | TOP10에 멀티모달 LLM(Claude Vision) 적용 시 신뢰도 R² 0.69 수준 |
| **Self-consistency 5회 평균** | 1회만 추론 | 점수 안정성 ↑ (특히 거리뷰 시점·조명 영향 완화) |
| **기준 객체 치수 프롬프트** | VLM 사용 X | 도로폭·건물높이 추정 시 필수 |
| **자동 Crop-Upsample** | 전체 이미지 그대로 SegFormer | 작은 객체(횡단보도 마킹, 그늘막 형태) 탐지 시 필요 |
| **컨텍스트·하네스** (재시도·검증·로깅) | 단순 호출 | LLM API 비용 추적 + 결과 안정성 |
| **Grounding DINO** | 안 씀 | text-prompt 기반 zero-shot 객체 탐지로 그늘막·가로수 자동 라벨링 가능 |
| **풀 GAN (Deep Umbra)** | 4시점 ray-cast로 단순화 | 다도시 전이 학습 + 더 정밀한 누적 그림자 |
